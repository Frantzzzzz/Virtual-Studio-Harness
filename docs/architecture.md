# 责任与模块边界

## 上游创作与下游执行

| 角色 / 层 | 负责 | 当前状态 |
|---|---|---|
| 剧作家 | 剧情因果、人物动机、初末状态、跨场依赖 | 本轮由宿主提供固定剧情；尚未接入自动编剧 |
| 动作导演 | 选择站位、路线、动作时刻、转向和道具事件 | 独立模型工单，使用 WorldOS 角色指导 |
| 摄影指导 | 镜头、构图、机位、运镜、切点 | 独立模型工单，读取同一影棚包与实际动作观察 |
| 共享影棚程序 | 场景事实、候选点、路线和可见性测量 | 复用 camera harness，局部参数由宿主给出 |
| 执行与检查 | 轨迹采样、Blender 写入、实际回读、净空与遮挡检查 | 实际小样已执行；提取版尚未端到端重跑 |

角色可以协商，但各自修改自己的计划。几何检查不代替导演作创意决策；执行器不通过拉伸时长、挪动人物等方式悄悄修正摄影问题。当前反馈由宿主转交，尚未实现自主三方协商或跨集修改依赖图。

## 共同接口

- `shared_studio.json`：场景哈希、坐标基准、角色尺寸、站位、路线摘要、交互锚点与摄影候选。
- `navigation_details.json`：候选站位和路径的实际几何检查，以及失败原因。
- `camera_catalog.json`：校准姿态、机位、镜头参数与可见性测量。
- `action_plan.json`：动作导演选择的有时间标记的根节点 / 姿态关键帧、道具持有事件与节拍。
- `actor_clip_manifest.json`：已烘焙动态场景、实际对象身份、帧率、帧数与场景版本。
- `camera_plan.json`：摄影指导选择的镜头区间、候选机位和静态 / 跟拍等方式。
- `film_checks.json`：实际动态场景上的失败镜头 / 帧段 / 对象，或对应检查范围内的通过结果。

这些输入和产物按场景版本绑定。候选机位在校准姿态通过，不意味着整段新动画通过；每次修改动作或摄影都需要相关复验。

## 当前配置化范围

已提取：本机文件路径、源场景哈希、局部原点和范围、十个命名站位、Blender / Codex 可执行程序、共享锁、字体与模型设置。

仍固定于 Forest 胶囊小样：三角色一盒、动作语义、桌面来自校准剧集、名称分类、角色尺寸、导航代理、校准姿态和五阶段摄影观察。`prior.py` 仍需既有校准动画。更换场景需要对应适配和重新测量，尚不能承诺只改路径即可运行任意 blend。

`prepare_whitebox.py` 原先的 Forest 聚合脚本没有复制进本仓库；本轮以已存在的派生场景和索引为输入。后续可将它单独参数化，不混入当前最小提取版。
